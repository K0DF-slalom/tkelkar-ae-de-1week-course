# AI-Accelerated Data Engineering - 1 Week Course

> Work in progress: this curriculum is still under development. Content, labs, and links may change.

## Overview

This repo contains a self-service, 5‑day curriculum with hands-on labs for AI‑accelerated data engineering, plus a Day 0 prerequisites and setup guide. Review [Day 0 — Prerequisites & Setup](day0/README.md) for access checks, tooling setup, and readiness before Day 1. Use the schedule below to navigate day-by-day; each `dayX/README.md` includes the agenda, key concepts, and exercises, and the goal is to finish the week with practical workflows you can reuse on real projects.

## Schedule & Content

- [Day 1 — Foundations & Governance](day1/README.md): AI/Codex fundamentals, prompting best practices, responsible use and guardrails, and context engineering basics.
- [Day 2 — Codex Engineering Patterns](day2/README.md): repeatable “spec → plan → implement → verify” workflows, refactoring patterns, tests as context rails, and small automation.
- [Day 3 — Advanced Codex for Data & Apps](day3/README.md): synthetic data processing pipeline (profiling, data-quality checks, metrics derivation, modeling), SQL refactoring/optimization, and safe legacy modernization patterns.
- [Day 4 — Mini Capstone Build](day4/README.md): build a small, working artifact end-to-end with strong context scaffolding and verification.
- [Day 5 — Demo, Feedback & Next Steps](day5/README.md): demo with evidence, peer review, and a concrete 30-day application plan.

## Best Suited For

- People who can be fully off-project for a week
- Upcoming client engagements needing AI-ready staff quickly
- Pilot cohorts or early adopters

## Expected Outcomes

- Confidence using Codex for daily engineering tasks
- A small modernization artifact completed as a mini-capstone
- Readiness to join AI-enhanced delivery pods (with support)
- Hands-on experience with Context Engineering and Product Requirements Prompts (PRP)

## Guidance (Self-Service)

- Use a **non-sensitive** practice repo and datasets (no client data, no secrets).
- Prefer well-known public datasets (e.g., Kaggle Titanic survival data, NOAA GHCN weather observations) for day-by-day labs and document provenance when you generate synthetic data.
- Timebox each day to ~8 hours including breaks; favor hands-on labs over reading.
- Keep a short daily log: what you tried, what worked, what you’ll reuse.
